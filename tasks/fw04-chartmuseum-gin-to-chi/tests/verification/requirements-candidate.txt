# The stack a candidate test may import, hash-pinned.
#
# Same versions as tests/behavioural/requirements-runner.txt, and that is the
# point rather than a convenience: a candidate is asked to write a test in the
# shape of a stage 2 test, so the library it writes against has to be the one
# stage 2 runs.  A candidate that passed here under a different pytest would be
# reporting on a suite the benchmark does not own.
#
# Nothing beyond the standard library for HTTP.  A candidate compares two servers
# byte for byte, and http.client shows a response as it came off the socket --
# header casing, header order, duplicate headers, the exact reason phrase, an
# empty body that is present versus absent.  A higher-level client normalises all
# of that away, so adding one would remove differences a candidate is hired to
# find.  urllib.request is available for the same reason and with the same caveat
# (it follows redirects unless told not to).
#
# PyYAML is here because index.yaml is the task's one structured document: a
# candidate that wants to claim two indexes disagree should be able to say which
# entry and which field, not print two YAML blobs.
#
# pytest-timeout so a candidate that writes a request with no deadline fails its
# own round instead of consuming the stage's wall clock.
#
# Installed with --require-hashes into /opt/venv, so a substituted artefact fails
# the build rather than the stage.
