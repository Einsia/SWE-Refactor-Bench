# The scan's runner, and nothing else.
#
# Four packages, hash-pinned, --no-deps: this is a test runner for checks that
# open files and read them.  Nothing here can build the submission, and that is
# the point of keeping the list this short -- the moment a Go toolchain or an HTTP
# client appears in this image, a scan module could compile the tree or start it,
# and stage 1's whole claim is that it cannot.
#
# No pytest-timeout and no PyYAML, unlike the behavioural stage's list.  A scan
# reads files and cannot wait on a socket, so there is no clock to install; and
# nothing here parses an index.yaml, because comparing that document against what
# it claims is behaviour and belongs to stage 2.
#
# The versions are the ones tests/behavioural/requirements-runner.txt already pins,
# so the scan runs on the same pytest the behavioural suite does and there is one
# version of the runner to reason about across the two stages.  Both hashes are
# listed for each package -- wheel and sdist -- because this image installs from a
# different base than the behavioural one and pip is free to prefer either.
