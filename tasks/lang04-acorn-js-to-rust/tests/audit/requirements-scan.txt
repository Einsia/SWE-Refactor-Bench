# The scan's runner, and nothing else.
#
# Four packages, hash-pinned, --no-deps: this is a test runner for a set of checks
# that open files, hash them, and read their first four bytes.  Nothing here can
# import, configure or build the submission, and that is the point of keeping the
# list this short -- the moment an HTTP client or a framework appears in this image,
# a scan module could start a service, and stage 1's whole claim is that it cannot.
# For this task the same argument runs through the toolchain: there is no cargo, no
# rustc and no node in the image, so a module that tried to build or run the
# submission would fail on the missing program rather than quietly grading a build.
#
# The versions and hashes are the ones every stage-1 image in this benchmark pins,
# so `swerefactor.pytest_module` -- the plugin that turns a pytest run into the check
# records the harness reads -- runs against the pytest it was written for.  Stage 2
# of this task pins nothing here because it needs no pytest at all: its driver is
# plain Python on the image's own interpreter, which is why the two stages'
# dependency lists have nothing to reconcile.
