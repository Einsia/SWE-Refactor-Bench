# What a stage-3 candidate may import beyond the standard library and srbsqlite.
#
# Not the product's dependency list -- SQLite has none, and the wasm build links
# one static libz that the image cross-compiles.  This is the test stack, and it
# is deliberately the same four pins the other two stages of this task use and the
# same four the rest of the benchmark uses.  One pytest per benchmark: a candidate
# whose runner differed between the two halves of a comparison would not be
# comparing the two builds.
#
# pytest-timeout is here and is not in the stage-1 list, because stage 3 runs code
# an adversary wrote against a wasm module that may loop.  A hang is a legitimate
# finding, and it has to be a finding rather than a stalled round: the timeout puts
# a ceiling on one test function, run-candidate.sh puts one on the whole file, and
# the harness puts one on the candidate.
#
# Deliberately absent: anything that speaks a protocol, and any wasm binding.  A
# candidate reaches the product through srbsqlite -- which runs the built CLI as a
# subprocess -- and through nothing else.  A python wasm runtime in this image
# would mean a candidate could execute the module under an engine that is not the
# one the task names, and the answer it got would be about that engine.
