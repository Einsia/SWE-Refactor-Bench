# The candidate's test stack for stage 3, hash-pinned.
#
# Not the library's dependency list -- go-yaml has none beyond the standard
# library, and the Zig port is required to have none at all.  This is what a
# candidate test file may import beyond the standard library and `srbyaml`.
#
# Both trees get these versions from this one venv.  A candidate whose pytest
# differed between the two halves of a comparison would not be comparing the two
# implementations, and "the original passes, the submission fails" is the entire
# verdict this stage produces.
#
# The same five versions lang01's stage 3 pins, so the benchmark runs one pytest.
# Python here is Debian bookworm's 3.11, so neither `exceptiongroup` nor `tomli`
# is in the closure -- both are conditional on 3.10 and earlier.  The five are the
# complete closure: pytest needs iniconfig, packaging and pluggy; pytest-timeout
# needs pytest.  `--require-hashes` refuses to install anything unlisted, so a
# sixth dependency appearing upstream fails the image build rather than arriving
# unpinned.
#
# `pip` itself is deliberately not upgraded before this file is installed, which
# is a small deviation from lang01 worth naming.  The venv's own pip is 23.0.1,
# which supports `--require-hashes`; upgrading it first would be one network
# fetch pinned by version but not by digest, and it would change nothing about
# what lands here, since every artefact below is verified by hash.
#
# Deliberately absent: PyYAML, ruamel.yaml, and anything else that parses YAML.
# A third implementation in this image would let a candidate compare against it
# instead of against the two trees, and a disagreement with PyYAML is not a
# defect in the port -- PyYAML implements a different YAML version than the one
# go-yaml does.  Also absent: httpx, requests, anything that speaks a protocol.
# A candidate reaches the library through `srbyaml` and the standard library, and
# `screen-candidate.py` refuses the imports that would reach anywhere else.
