# The suite's runner, and nothing else.
#
# Five packages, hash-pinned, --no-deps. There is no HTTP client here and no
# framework: this stage's Python never talks to the app. Node drives the two
# bundles and writes two JSON files; every pytest module in the suite loads those
# files and compares them. Anything else in this list would be a dependency for a
# capability the stage does not have.
#
# The target stack is npm's, and it is not installed here from a pin list at all
# -- it comes out of the offline cache minted from allowlist-package-lock.json,
# which is the same cache and the same lockfile the agent's environment image
# used. Two copies of that pair exist for Docker context reasons and `swerefactor
# validate` checks they are byte-identical.
#
# pytest and pytest-timeout are the same versions tests/audit's
# requirements-scan.txt pins, so there is one runner version to reason about
# across the three stages.
