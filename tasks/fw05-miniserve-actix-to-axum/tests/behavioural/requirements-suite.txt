#
# The behavioural suite's own Python dependencies: pytest, and the two content
# decoders the recording cannot be read without.
#
# Hash-pinned because the image is the grader: an unpinned install makes the
# measurement depend on the day the image was built.  The versions are fw01's,
# deliberately.  Two tasks in this bench pinning different pytest majors would
# mean a module's collection semantics depend on which task it lives in, and the
# one semantic this suite leans on -- what an empty parametrisation scores -- is
# exactly the kind of thing that shifts between majors.
#
# Brotli and zstandard are here because miniserve compresses with them and the
# recording holds the decoded result.  State A's Cargo.toml turns on actix-web's
# `compress-brotli`, `compress-gzip` and `compress-zstd`, so a request carrying
# `Accept-Encoding: br` is answered `Content-Encoding: br`, and `normalize.record`
# stores that response's *decompressed* body: its text, its length, its parsed
# HTML.  gzip and deflate come out of the standard library, and for a long time
# that made the omission of these two invisible -- `cp-gzip` and `cp-deflate`
# passed, so compression looked covered.  It was not.  `decompress()` raises
# ValueError when the module is missing, `record()` catches it as a decode
# failure, and the three cases that negotiate br or zstd (`cp-br`, `cp-zstd`,
# `cp-qvalues`) come out with `decompressed: false` and no html at all.  Against a
# recording that has all three decoded, that is 72 failed checks in `encodings`
# for a server that did exactly what it was asked -- the grader was the thing that
# could not hold up its end.
#
# So this is not a client library sneaking in through the back door.  The
# distinction is what the code does to the bytes: an HTTP client would decide for
# the suite how a response is framed and normalise what this task grades, whereas
# these two invert a transformation the server announced in a header, and their
# output is compared to output that the same two calls produced.  Reading the
# recording requires the same decoders that wrote it.
#
# Wheels for cp310 and cp311 are both pinned, plus each sdist, for the same reason
# the conditional pytest dependencies below are pinned: the image is 3.11 and the
# suite is developed on 3.10, and a pin list that only installs in one of those
# cannot be checked in the other.  Neither package needs cffi on CPython --
# zstandard asks for it only under PyPy and under its `cffi` extra -- so there is
# no transitive hash missing here.
#
# What is NOT here is the more interesting half:
#
#   * No HTTP client.  The harness speaks HTTP over `socket` and `ssl` from the
#     standard library, because a client library normalises the things this task
#     grades -- header case and order, a chunked body's framing, a 304 that
#     carries no body, a connection closed mid-response.  requests or httpx would
#     hand back a tidied version of the response and the tidying would be
#     invisible in the diff.
#
#   * No pytest-timeout.  It guards a hang, and every blocking path here is
#     already bounded by its own deadline: sockets by SRB_REQUEST_TIMEOUT (60s)
#     and SRB_READY_TIMEOUT (90s), the CLI by subprocess timeout, process exit by
#     wait(timeout=10).  The thirteen comparison modules do no I/O at all -- they
#     read one JSON recording -- so there is nothing in them to hang.  A pinned
#     dependency that guards nothing still has to be fetched at image-build time,
#     and can still fail there.
#
#   * Nothing for reading TOML on 3.11.  The harness reads suite.toml through the
#     infra image's swerefactor.tomlcompat, and 3.11 has tomllib.
#
# exceptiongroup and tomli are pytest 8.3.4's own conditional dependencies below
# Python 3.11.  The image is bookworm's python3, which is 3.11, so pip's markers
# drop both there.  They are pinned anyway so this same file installs on a 3.10
# host -- which is where the suite gets developed, and a pin list that only works
# in the image cannot be checked before the image is built.
#
