# group:artifact:version:packaging[:classifier]
# Measured from a real Maven State A build plus the reference
# Gradle State B build. Fetched at image-build time only.
#
# "A real State A build" includes its release profile: maven-source-plugin
# produces the sources jar that data/pom.json requires beside the artifact, and
# resolving that plugin's own descriptors pulls in ~90 coordinates the default
# build never touches (maven-archiver, plexus-archiver, plexus-io and their
# ancestry). They are inert for a Gradle build, which produces the same sources
# jar from a task rather than a plugin, and they are here so the publication both
# trees are measured on is reproducible offline.
# maven-install-plugin:3.1.2's own dependencies. Reached only by `mvn deploy`,
# which runs the install phase before the deploy phase, so a closure built for
# `mvn package` does not hold them and the publish configuration cannot build.
#
# maven-javadoc-plugin:3.4.1's own dependencies, for the same reason and with one
# trap. The release profile binds it, so `mvn deploy` resolves the plugin before
# it executes any goal -- which means -Dmaven.javadoc.skip=true cannot rescue an
# incomplete closure: `skip` is read by the goal, and a plugin whose descriptor
# will not resolve never reaches its goal. The trap is the classifier. Upstream
# renamed sisu-guice's AOP-free variant `noaop` -> `no_aop` between 2.x and 3.x,
# so the 2.1.7 line below and the 3.2.3 one spell it differently and a fetcher
# run with -Dtransitive=false takes the manifest literally. Both spellings are
# required: 2.1.7:noaop for the older plugin ancestry, 3.2.3:no_aop here.
